# Private API

Node.js 24 or newer runs the Hono API. `npm run dev` starts it on port 3001 behind Vite's same-origin `/api` proxy. Development first-run setup works only when the actual API connection and browser hostname are localhost. A phone on the LAN cannot initialize the password; set it on the computer first, or set `APP_PASSWORD` in the local environment. Passwords must contain 12–256 characters.

For a deployment, set `NODE_ENV=production`, a strong `APP_PASSWORD`, `APP_ORIGIN=https://your-host.example`, and `DATABASE_PATH=/data/exchange-life.sqlite`; run `npm run build` then `npm start`. Mount `/data` on persistent storage. The production API also serves `dist/`, so frontend, uploads and API share one HTTPS origin. Terminate HTTPS at the hosting platform or reverse proxy and restrict direct public access to port 3001. The deployment password is required at startup; changing it revokes existing sessions.

The SQLite database contains all records, original normalized image uploads, hashed passwords, hashed session tokens and cached public exchange rates. There are no seed records. Back up the database with SQLite's online backup facility or stop the app before copying the database and its WAL/SHM files. Do not use a stateless/serverless filesystem or run replicas against separate databases. Export is an authenticated JSON backup containing all personal records and originals with MIME, filename, timestamps and base64 bytes; it excludes credentials and sessions. There is no import endpoint in this version.

Cookies are HttpOnly, SameSite=Lax, valid for 30 days, and Secure in production. The native iOS container should load the configured HTTPS deployment origin so cookie authentication and protected image requests stay on that origin. An unrelated `capacitor://localhost` origin and a separately hosted API are not supported by this cookie mode. `APP_ORIGIN` may contain comma-separated explicitly permitted web origins; this does not override browser third-party-cookie rules. No passwords, sessions, records or images belong in browser localStorage or service-worker caches.

Every mutating API request requires `X-Requested-With: ExchangeLife`. Cross-origin requests are rejected unless explicitly configured. Login is limited to eight attempts per connection address and thirty total per fifteen minutes. The API uses the socket peer address, never a client-controlled forwarded header. Behind a proxy the per-address limit therefore applies to the proxy; this is suitable for the intended single-person service.

`GET /api/rates?base=EUR&quote=CNY` gets Frankfurter v2 reference rates and observations from the preceding 30 calendar days. `date=YYYY-MM-DD` requests historical observations. Weekend/holiday dates return the most recent actual observation and expose its `date`. Missing days are not interpolated. Cached latest queries refresh after one hour, historical queries after one day. During an outage, available cache returns `stale: true`; unavailable data returns 503. A rate more than seven days behind its requested date is also stale. These are reference rates, not a bank's execution quote. Official API documentation: https://frankfurter.dev/.

Expenses always use the server's historical conversion to the current profile base currency; submitted `rate` and `baseAmount` fields are ignored. Stale/unavailable cross-currency rates block saving rather than producing an uncertain total. Same-currency amounts use the mathematical identity rate 1. Once expenses exist, changing the base currency returns 409 so reports cannot mix different base currencies. Expense and exchange dates cannot be in the future in the configured timezone.

`POST /api/uploads` accepts a multipart `image` field containing JPEG, PNG or WebP of up to 8 MB. MIME and file signature must agree and image dimensions are bounded. The client normalizes camera/library files before upload; the normalized image is the stored original. Images remain authenticated and are served with `nosniff`, `no-store` and a restrictive content policy. Replacing/removing a document deletes its old image once no document references it. Referenced images cannot be deleted directly.

Run `npm test` for isolated in-memory/file-backed security, persistence, validation, conversion, concurrency and original-export tests. Test fixtures never populate the real application database.
