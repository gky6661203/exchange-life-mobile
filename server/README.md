# Account API

The active API lives in worker/index.ts and worker/accounts.ts. Sites binds Cloudflare D1 and R2. Local development and self-hosting use the same routes through server/account-backend.ts, with SQLite adapters. server/index.ts starts this account backend; the previous single-password server/app.ts is retained for compatibility tests and is not served.

Register with POST /api/auth/register (name, email, password), log in with POST /api/auth/login (email, password), check GET /api/auth/status, and log out with POST /api/auth/logout. Registration passwords require 12–256 characters. Email is normalized to lowercase. Passwords use salted scrypt (N=32768, r=8, p=3); random 256-bit session tokens are stored as SHA-256 digests. Cookies are HttpOnly, SameSite=Lax, valid for 30 days and Secure on HTTPS / self-hosted production. Logout deletes the server session. Email verification and email-based password recovery are not implemented; registration discloses this.

All personal routes, image reads and exports require a valid account session. Data ownership is bound server-side to an account UUID. Registering an existing legacy Email does not expose old records. Legacy records remain unchanged and may only be linked if the Sites edge supplies matching trusted user ID and Email headers. Local clients' platform identity headers are stripped.

Mutations require X-Requested-With: ExchangeLife; cross-site requests are rejected. Auth attempts are persisted in D1 and limited to 40 per IP and 12 per normalized Email in each 15-minute window. Site dispatch supplies the IP. Local development shares one local rate-limit bucket. Accounts, profiles, all collections, uploads and exports are isolated by data owner.

Local use: Node.js 24+, npm ci, npm run dev. A new data/accounts.sqlite holds accounts and records; old data/exchange-life.sqlite files are not overwritten or automatically claimed. SQL migrations in drizzle/ apply once locally and are included in Sites builds. Back up the database and its WAL/SHM files with SQLite's backup facility, or stop the app before copying them. Deploy a single self-hosted instance with persistent storage. Set NODE_ENV=production, APP_ORIGIN=https://your-host.example and DATABASE_PATH, serve behind an HTTPS proxy, and restrict direct public access to port 3001. No shared APP_PASSWORD is needed.

npm test includes account registration, normalized duplicate Email, session expiry/logout, CSRF, failed-login limiting, and cross-account read/write/photo/export tests. Test databases are isolated from daily records. Older compatibility tests cover the retired single-user API.
